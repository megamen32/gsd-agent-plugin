# Megamen32 GSD

[English](../README.md) · [Почему именно эта версия](EVALUATION.md) · [Оригинальный GSD](https://github.com/gsd-build/get-shit-done)

> Моя автообновляемая версия Get Shit Done: весь upstream GSD плюс фокус-группы и обязательная проверка результата на реальном пользовательском пути.

В наших внутренних сравнениях GSD оказался сильнейшей основой по всем
проверенным критериям. Этот репозиторий содержит версию, которую я использую и
распространяю: upstream-планирование, исполнение и UAT дополнены теми проверками,
которых не хватало для честного заявления «готово».

- Фокус-группы для интерфейсов, онбординга, понятности и пользовательских текстов.
- Финальная канарейка через настоящий браузер, приложение, телефон, CLI, API или канал доставки.
- Надсмотрщик, который автоматически возвращает исполнителя от технических отчётов к бизнес-задаче и канарейке.
- Понятные человеку уведомления и естественная русская речь TTS по умолчанию.
- Ежедневное проверенное обновление из upstream без потери персонального слоя.
- Codex, Claude Code, OpenCode и ZCode из одного публичного репозитория.

## Установка в Codex

```bash
codex plugin marketplace add megamen32/megamen32-public-marketplace --ref main
codex plugin add gsd@megamen32-public
```

После установки откройте новую сессию Codex. Обычные навыки `gsd:*` продолжат
работать, а команды, способные объявить задачу завершённой, автоматически
подключат персональный acceptance gate.

Перед уходом GSD от результата в хэши, координацию или бюрократию вокруг
безопасности, а также перед завершением хода с выполнимой работой,
автоматически запускается один короткий разбор
надсмотрщика. Он выбирает конкретное следующее действие, исполнитель делает его
сразу и продолжает обычный GSD, не ожидая от пользователя «продолжай».
Надсмотрщик не создаёт ещё один отчёт и не отменяет
реальные ограничения или необходимые исправления. Его можно вызвать явно:
`gsd:gsd-business-supervisor`. Обёртка действует внутри запущенного GSD, а не как
фоновый наблюдатель за всеми чатами; обновления upstream её сохраняют.

## Как это обновляется

Upstream не редактируется вручную. Скрипт собирает свежий опубликованный GSD,
поверх него повторно накладывает содержимое `overlay/`, запускает тесты и
пользовательскую CLI-канарейку. В `main` попадает только прошедшая проверку
сборка.
